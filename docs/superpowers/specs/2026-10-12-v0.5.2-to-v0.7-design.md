# v0.5.2 → v0.7.0 设计方案

日期：2026-10-12
状态：已评审（2026-10-12），D1–D6 全部按推荐执行
范围：2026-10-12 全仓 review 的问题修复，以及路线图功能的落地顺序。群晖 SPK 不在本方案内，后续单独出方案。

## 0. 总体安排

| 版本 | 主题 | 是否改 config schema | 是否改协议 |
|---|---|---|---|
| v0.5.2 | 修复漏关 / 误关 / 关机失败；引入「断电周期」模型 | 只新增和收紧校验，不删字段 | 新增可选字段 + 新 ack 状态 `simulated`（**先升 master 再升 slave**） |
| v0.6.0 | 策略防抖、通信丢失兜底、config v2、per-node token、HTTPS admin、SNMP profile | 是（破坏性，集中在这一版） | 新增 token 下发字段 |
| v0.7.0 | NUT 兼容（服务端子集 + 数据源）、多 UPS、slave 端失联兜底 | 是（新增） | 新增 `ups_state` 消息 |

不做：Web 状态页换前端框架（删出路线图）、SSE 推送（延后，等有事件总线再说）、双 master HA（由 v0.7 的 slave 端失联兜底替代）。

所有带输入输出契约的修复先写失败测试，再改实现。

## 1. v0.5.2：修复

### 1.1 核心改动：引入「断电周期」(episode)

现状的问题都出在同一处：自动关机只有一个全局 `autoShutdownLatched` 和一个 `activeCommand`，命令「完成」就清掉 `activeCommand`，锁存要等市电恢复才清。这导致：

- 第一条策略触发后，后续策略在同一次断电里被 `errShutdownAlreadyActive` 拦下（`shutdown.go:65`，`ups.go:49` 吞掉错误）。
- 节点回报 `failed` 后命令算完成，`activeCommand` 被清，重放依赖 `activeCommand`，所以不会重试。
- 按 tag / node_id 下发的命令，触发时离线的节点重连后收不到重放（`shutdown.go:483` 只对 `all` 收编）。

**新模型**：一次断电 = 一个 episode = 一条自动命令，目标集合在 episode 内只增不减。

```go
type autoEpisode struct {
    StartedAt    time.Time
    CommandID    string              // 本 episode 的自动命令
    FiredPolicies map[string]struct{} // 已触发过的策略名
}
```

规则：

1. **episode 开始**：UPS 成功轮询读到 `OnBattery == true` 且当前没有 episode。
2. **策略评估只在 episode 内进行**。市电下不评估任何策略（修掉「不带 on_battery 的策略在市电下反复触发」，`ups.go:38-48`）。
3. **首次命中**：创建自动命令，目标 = 命中策略目标的并集，记录 `FiredPolicies`。
4. **后续命中新策略**（不在 `FiredPolicies` 里）：不新建命令，**合并进本 episode 的命令**：
   - 把新目标并入 `Message.Target`（任一新策略是 `all` 则 `Target.All = true`）；
   - 新增的在线目标节点加入 `TargetNodes` 并立即下发；
   - 同一个 `CommandID` 继续用，slave 端对新节点来说是第一次收到这个 ID，不影响去重。
5. **重连收编**：节点重连时，只要它匹配命令的 `Target`（all、node_ids 或 tags 任一），就加入 `TargetNodes` 并重放。tag 匹配用注册消息里的 tags。
6. **episode 内命令不因「完成」而释放**：`activeCommand` 只在 episode 结束或手动 reset 时清空。`failed` / `timeout` 的节点按 1.3 的规则周期重试。
7. **episode 结束**：成功轮询读到 `OnBattery == false`。清 episode、清 `activeCommand`（自动命令），命令标记 `ReplayDisabled`，不再重放。
8. **持久化**：episode 写入 state 文件，替代 `AutoShutdownLatched`。

手动命令和自动命令的关系：

- 手动命令（`POST /commands/shutdown`）保持现有语义：完成即释放。
- episode 内再发手动命令：返回 409（与现在相同）。
- 手动命令进行中，自动策略触发：**自动优先**。手动命令标记 `ReplayDisabled` 并结束，创建 episode 命令。理由：真实断电比人工测试重要，不能被一条卡住的测试命令拦住（现在 `activeCommand` 被 timeout 钉住时就是这种情况）。

### 1.2 master 本机关机（local_shutdown）的启用条件

现状：任何命令都会启动 local_shutdown，包括手动给单个节点发的测试命令和 `dry_run: true` 的命令（`shutdown.go:79`，`local_shutdown.go:161`）。

改为：

- **只有目标为 `all` 的命令**才启动 local_shutdown 的等待流程；episode 合并升级到 `all` 时也在那一刻启动（`StartedAt` / `DeadlineAt` 从升级时刻算起）。
- **dry-run 判定按命令**：`runLocalShutdownCommand` 用命令的 `Message.DryRun`，不再只看 `cfg.DryRun`。
- **emergency 独立于命令**：episode 内只要 `RuntimeMinutes < emergency_runtime_minutes`，不管有没有 `all` 命令，都补发一次当前命令并关本机。这样即使用户的策略里没有 `all` 目标，master 也有兜底。
- **目标为空也照常建命令**（自动触发时）。现状 `selectTargets` 为空直接报错，交换机先掉电时 master 永远不关自己（`shutdown.go:53`）。空目标的命令 `remoteShutdownFinished` 为 false，master 等到 `max_wait` 或 emergency 再关。手动命令目标为空仍返回 400。
- **本机关机失败后重试**：phase 为 `failed` 时，每 30s（具名常量）重试一次，episode 结束则停止。现状失败一次就不再处理。

### 1.3 失败节点重试

- `failed` / `timeout` 的节点：在 episode 内由 command watcher 每 30s（与 1.2 共用常量）重发一次。slave 端已支持对 `failed` 状态的命令重新执行（`slave/client.go` `resumeShutdown`）。
- `shouldReplaceShutdownUpdate`：允许 `failed` 被后续的 `executing` / `executed` 覆盖。现状 `failed` 算 final，重试成功的回报会被丢弃。
- `status_class.go` 中 `failed` 仍是 `final`（local_shutdown 不无限等失败节点），但不再是 episode 命令的「释放」条件（见 1.1 第 6 条）。
- master 收到不在白名单内的 ack 状态时丢弃并记日志（现状任意字符串都会写进 `NodeUpdates`）。

### 1.4 旧配置 `shutdown_policy` 的电池条件反转

- `config.go:309`：`require_on_battery: false` 合成为 `OnBattery = nil`，不再是 `&false`。
- 合成出的 default 策略走同一套校验：没有任何 when 条件时报错。配置里两种策略都不写 → 启动失败，错误信息指向 `shutdown_policies`。
- 由于 1.1 的「只在 episode 内评估」，`when.on_battery: false` 不再有意义。v0.5.2 中配置为 `false` 时报错；`true` 和不写等价。字段本身在 v0.6 删除。
- 删除已无调用方的 `ShouldShutdown`。

### 1.5 命令 ID 全局唯一

- 格式：`shutdown-<UTC 时间 20261012T101500Z>-<8 位随机 hex>`，随机数用 `crypto/rand`。
- 删除 `commandSeq` 及其持久化字段。
- slave 端 `commandStates` 加上限（200 条，与 master 的 `maxRetainedCompletedCommands` 同值），按 `AckedAt` 裁剪最旧的。

### 1.6 dry-run 单独一个 ack 状态

- 新状态 `simulated`：slave 在 dry-run（命令或本地配置）下回报 `simulated`，不再回 `executed`。
- `status_class.go`：`simulated` 为 `complete + final + replayDone`。
- Prometheus status label 白名单加上 `simulated`。
- `/status` 和状态页把 `simulated` 单独显示。
- 兼容性：旧 master 不认识 `simulated`，会把节点记为 timeout。**升级顺序必须先 master 后 slave**，写进 release notes 和 `docs/upgrade.md`。

### 1.7 关机权限：systemd 沙箱与 sudoers

现状两处都会让 `sudo -n /sbin/shutdown` 失败：

- `nut-master.service` 显式 `NoNewPrivileges=true` + `RestrictSUIDSGID=true`；`nut-slave.service` 以非 root 运行并设了 `LockPersonality`、`RestrictAddressFamilies`、`SystemCallArchitectures`，按 systemd 文档会隐式开启 NoNewPrivileges。
- sudoers 条目末尾的 `""` 在有其他参数时会让匹配失败（只有不带其他参数时 `""` 才表示「禁止带参数」）。

方案（**待决策 D1**）：

- **方案 A（推荐用于 v0.5.2）**：保留 sudo。两个 unit 删掉会隐式开启 NoNewPrivileges 的选项（`NoNewPrivileges`、`RestrictSUIDSGID`、`LockPersonality`、`RestrictAddressFamilies`、`SystemCallArchitectures`，以及 systemd 文档中列出的同类选项），保留 `ProtectSystem=strict`、`ProtectHome`、`PrivateTmp`、`ReadWritePaths` 等文件系统隔离。sudoers 中带参数的条目去掉末尾 `""`（sudo 对带参数的条目本来就是整串精确匹配）；`/sbin/poweroff ""` 这类无参数条目保留。
- **方案 B**：去掉 sudo，改用 `systemctl poweroff` + polkit 规则授权 `nut-server` 用户调用 `org.freedesktop.login1.power-off`，沙箱可以全保留。代价：依赖 polkit；Debian 11 / Ubuntu 22.04 的旧 polkit 用 `.pkla` 而不是 JS 规则，要维护两套；最小化安装可能没有 polkit。

**启动自检**（两个方案都做）：

- slave（非 dry-run）和 master（`local_shutdown.enabled` 且非 dry-run）启动时检查关机命令是否可执行：
  - 命令以 sudo 开头：执行 `sudo -n -l <去掉 sudo 及其选项后的 argv>`，退出码 0 表示允许。这个检查本身也要经过 setuid，所以也能发现 NoNewPrivileges 问题。
  - 否则：检查 `argv[0]` 是绝对路径且可执行。
- 失败时：ERROR 日志，slave 指标 `nut_slave_shutdown_ready 0`，并通过注册消息告诉 master（见 1.8）。**不退出进程**，避免 systemd 重启循环掩盖问题。
- CI：在 GitHub Actions 的 ubuntu runner（有真实 systemd）上安装 .deb，用随包的 unit 启动 slave，检查日志里的自检结果。这一步覆盖 unit + sudoers 的真实组合，不会真的关机。

### 1.8 注册消息新增字段

`RegisterMessage` 新增两个可选字段（旧 master 忽略未知字段）：

```go
DryRun        bool   `json:"dry_run,omitempty"`
ShutdownReady *bool  `json:"shutdown_ready,omitempty"` // 启动自检结果
```

master 存进节点目录，`/status`、状态页、`nut_master_nodes` 相关指标展示。运维从 master 一处就能看到哪些节点还在 dry-run、哪些关不了机。

### 1.9 SNMP 解码

- 检查 `packet.Error != gosnmp.NoError`，非零即本次轮询失败。
- 只接受整数类 PDU（`Integer`、`Gauge32`、`Counter32`、`Uinteger32`、`TimeTicks`），`Null` / `OctetString` 等一律报错。现状 `gosnmp.ToBigInt` 对这些类型返回 0，被当作电量 0、续航 0（`snmp.go` 中 `value == nil` 分支永远不成立）。
- `snmp.version: "3"` 在 v0.5.2 中配置校验直接拒绝（现在没有 USM 参数，每次轮询必失败）。v0.6 正式支持。

### 1.10 master 重启后的重放时机

master 断电自关、来电启动后，会恢复 state 中的 episode。slave 可能先于 UPS 网卡上线，刚开机就收到重放。

改为：恢复出的 episode 在**第一次成功轮询之前不重放**。第一次轮询为市电 → 结束 episode；为电池 → 正常重放。手动命令不受影响。

### 1.11 其他小修

- slave 拨号：`net.Dialer{Timeout: 10s}` 和 `tls.Dialer`，握手受同一超时约束（`slave/client.go:170,179`）。
- master `Accept` 遇到非关闭类错误（如 EMFILE）：退避后继续，不再让 `Run` 返回导致进程退出（`server.go:140`）。
- admin 与 slave metrics 的 `http.Server` 设 `ReadHeaderTimeout`；admin 写接口用 `http.MaxBytesReader`（64 KiB）。
- `tls.bind_node_id_to_cert: true` 但未开 `require_client_cert` → 配置报错（现状静默不生效）。设了 `tls.ca_file` 但未开 `require_client_cert` → 配置报错。
- `TimeoutSeconds` 上限校验（24h），防止溢出成负数。
- postinst：`/etc/nut-server` 改为 `root:nut-server`、目录 0750、配置 0640；状态目录单独归 `nut-server`。与 `install-master.sh` 保持一致。
- CI：action 钉 commit SHA；`build.yml` 加 `permissions: contents: read`；release 前跑完整测试；nfpm 下载后校验 SHA256；Go 升级到当前受支持版本。

### 1.12 v0.5.2 测试清单

每条先写失败测试：

- 多策略逐级：`dev-early` 触发后，`critical-all` 命中时 dev 以外的节点收到同一 command_id。
- 市电下 `charge_below` 策略不触发。
- 手动单节点命令不启动 local_shutdown；`dry_run: true` 的 all 命令不执行真实本机关机。
- 无在线 slave 时自动触发仍建命令，`max_wait` 到期后执行本机关机。
- `failed` 节点 30s 后收到重发，之后回报 `executed` 能覆盖 `failed`。
- tag 目标命令：触发时离线的节点重连后收到重放。
- `require_on_battery: false` 合成的策略不再要求市电；两种策略都缺失时启动报错。
- 命令 ID 在 state 文件丢失后不重复。
- SNMP：`packet.Error` 非零、Null 值、OctetString 值都返回错误。
- 恢复出的 episode 在首次成功轮询前不重放。
- 关机权限自检：sudo 允许 / 拒绝 / 非 sudo 命令三种情况（用可注入的 exec 函数测）。

## 2. v0.6.0：策略与认证

这一版集中做所有破坏性 config 变更，升级时运维只需要改一次配置。

### 2.1 策略防抖

```yaml
shutdown_policies:
  - name: critical-all
    when:
      runtime_below: 5
    duration: 30s        # 连续满足 30s 才触发；缺省 0 = 立即
    target: { all: true }
```

- 每条策略在 episode 内维护 `firstMatchedAt`。命中时若为空则记下；不命中则清空。
- 轮询失败**不清空**计时，也**不触发**：触发要求截止时刻之后至少有一次成功且命中的轮询，避免用旧数据做决定。
- 防抖状态不持久化：master 重启后重新计时，这是更保守的方向。

### 2.2 通信丢失兜底

断电期间 SNMP 连不上时，现状完全不做决策。新增 when 条件：

```yaml
when:
  ups_unreachable_for: 2m
```

- 条件成立：在 episode 内（即最后一次成功轮询显示电池供电），且距离最后一次成功轮询已超过该时长。
- 与其他条件同样是 AND 关系，可以单独成一条策略。
- emergency（1.2）也加一个对应规则：episode 内 UPS 失联超过 `local_shutdown.unreachable_after`（缺省等于 `max_wait`）时，按 emergency 处理。

### 2.3 config v2（破坏性）

- 删除 `shutdown_policy`（旧格式）；必须写 `shutdown_policies`，至少一条。
- 删除 `when.on_battery`（episode 内评估已隐含电池供电）。
- YAML 严格解析：`yaml.Decoder.KnownFields(true)`，未知字段直接报错。
- 新增 `nut-master -check-config` / `nut-slave -check-config`：只加载和校验配置并运行 1.7 的关机权限自检，然后退出。安装脚本和 postinst 在启动服务前调用。
- `docs/upgrade.md` 给出旧配置到新配置的逐字段对照。

### 2.4 per-node token

现状：`auth_tokens` 全局共享，持有它的任何人都能用别人的 `node_id` 注册，`registry.Set` 会踢掉真节点（`registry.go:18`），关机命令随后发给冒充者。

方案（**待决策 D2**，推荐 A）：

**方案 A：注册时自动签发（enrollment）**

- `auth_tokens` 改名为 `enrollment_tokens`，语义为「首次注册用」。
- 某个 `node_id` 第一次用 enrollment token 注册成功时，master 生成 32 字节随机 token，在 `register_ack` 里返回；master 只保存其 SHA-256。
- slave 把签发的 token 写进自己的 state 文件（0600），之后用它注册。
- 一旦某个 `node_id` 有了签发的 token，enrollment token 就不能再以这个 `node_id` 注册。
- `enrollment: open | closed`（默认 open）。整个集群都注册完后设成 closed，泄漏的 enrollment token 就失效了。
- `DELETE /nodes/{id}/token`：吊销，节点需要重新注册。
- `/install/slave` 直接为目标节点签发 token，写进生成的装机脚本，不再下发共享 token。
- 优点：现有 slave 升级后下一次连接自动拿到自己的 token，不需要逐台手工改配置。

**方案 B：静态配置映射**

```yaml
node_tokens:
  web-01: "<token>"
```

运维为每个节点生成 token 并写进 master 配置。实现最简单，但每台 slave 都要手工迁移，新增节点也要改 master 配置并重启。

两个方案都需要：`security.ValidateToken` 改为返回匹配到的身份，而不只是 bool；token 校验前统一做 SHA-256，消除现有实现按长度提前返回、会泄露 token 长度的问题。

### 2.5 HTTPS admin

```yaml
admin_tls:
  cert_file: /etc/nut-server/tls/admin.crt
  key_file: /etc/nut-server/tls/admin.key
```

- 单独的配置块，不复用 slave 监听口的 `tls`（那里带 `require_client_cert`，语义不同）。
- 最低 TLS 1.2。证书只在启动时加载，不做热更新。
- `admin_listen_addr` 不是回环地址、又没配 `admin_tls` 时，启动打 WARN。
- 文档和状态页里写死的 `http://127.0.0.1:9001` 改为按配置生成。

### 2.6 装机接口重做

`GET /install/slave` 有副作用（把节点标为 expected），而且生成的命令总是带 `--disable-tls`（`install.go:68` + `quick-install-slave.sh:38`）。

- 改为 `POST /nodes/{node_id}/install-script`。
- master 开了 TLS 时，脚本带上 `--tls-server-name` 和 CA 证书内容（base64 内嵌，slave 端落盘为 `ca.crt`）。
- token 走 2.4 签发的 per-node token；不再作为命令行参数传给 `sudo bash`，改为在脚本内用 heredoc 写入配置文件，避免出现在 `ps` 里。
- 脚本 URL 固定到 release tag，不再在 `latest` 时用 master 分支。

### 2.7 SNMP profile 与 SNMPv3

```yaml
snmp:
  target: 10.0.0.31
  profile: apc            # ups-mib（默认）| apc | cyberpower | eaton
  # 可选：覆盖 profile 中的单项
  on_battery:  { oid: ".1.3.6.1.4.1.318.1.1.1.4.1.1.0", values: [3] }
  charge:      { oid: "...", scale: 1 }
  runtime:     { oid: "...", unit: timeticks }   # minutes | seconds | timeticks
```

- profile 是 OID + 判定值 + 单位的预设，代码里不写厂商分支。
- 初始预设（**OID 需要对照厂商 MIB 文件并在真机上验证后才能发布**）：

| profile | 电池供电判定 | 电量 | 续航 |

## 3. v0.7.0：生态兼容（概要，开工前各自单独出详细方案）

### 3.1 master 作为 NUT 数据源（upsd 子集）

让只能当 NUT client 的设备（群晖、QNAP、TrueNAS、ESXi 插件等）直接挂到 master 上。

- 监听 3493，实现 `VER`、`NETVER`、`USERNAME`、`PASSWORD`、`LOGIN`、`LOGOUT`、`LIST UPS`、`LIST VAR`、`GET VAR`、`PRIMARY`/`MASTER` 的只读子集。
- 变量：`ups.status`（OL / OB / LB / FSD）、`battery.charge`、`battery.runtime`（秒）、`device.mfr` / `device.model`。
- 关机语义：NUT client 不回 ack，master 无法逐个确认。把每个虚拟 UPS 名映射成一组节点，当 episode 命令的目标覆盖这组节点时，对该 UPS 名置 FSD；client 断开即视为已执行。
- 待调研：群晖固定使用的 UPS 名和账号（社区资料常写 `ups` / `monuser` / `secret`，需要以官方文档或抓包为准）。

### 3.2 NUT upsd 作为 UPS 数据来源

homelab 里大量 UPS 只有 USB 口，没有 SNMP 卡。新增 `ups.source: nut`，连接现有的 upsd 读 `ups.status` / `battery.charge` / `battery.runtime`。与 2.7 的 SNMP profile 并列，在轮询层抽出 `UPSReader` 接口。

### 3.3 多 UPS

- `upses: [{ id, source, ... }]`，策略增加 `ups: <id>`，`local_shutdown.ups` 指定给 master 自己供电的那台。
- episode、防抖计时、emergency 全部按 UPS 区分：episode 结构届时加 `UPSID`，单例改成按 UPS 的 map（v0.5.2 未预留该字段，避免提前引入用不到的结构）。

### 3.4 slave 端失联兜底（替代双 master HA）

- 新协议消息 `ups_state`：master 每次轮询后推送 `{on_battery, charge, runtime, episode_started_at}`。
- slave 配置 `failsafe: { enabled, after: 5m }`：最后一次收到的状态是电池供电，且与 master 失联超过 `after`，就本地关机。
- 不处理「master 挂了之后市电恢复」的情况：slave 只能按最后已知状态判断，这一点写进文档。
